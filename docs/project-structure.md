# Структура проекта

Этот файл объясняет, зачем нужны папки в проекте и что разработчику стоит в них менять.

## `src/`

Основной код бота.

Сейчас папка намеренно маленькая:

- `index.ts` — точка входа приложения.
- `browser.ts` — Playwright-сессия Mangabuff: ручная авторизация, сохранение сессии и проверка входа.
- `navigation-policy.ts` — общий скользящий бюджет браузерных навигаций Mangabuff.
- `trades.ts` — браузерный сценарий вкладки "Предложения": поиск видимых ссылок, локальная дедупликация, клики по обмену и запрошенной карте, проверка "Хотят получить", рангов и принятия.
- `card-locking.ts` — браузерные сценарии обхода всех или первых N недавних карт и их блокировки по порогу страниц желающих.
- `domain.ts` — доменные типы: статусы обменов, ранги карт, настройки бота.
- `db.ts` — SQLite-схема и базовые функции работы с историей обменов.
- `rules.ts` — правила принятия обменов: страницы желающих и ранговая компенсация.
- `ranks.ts` и `rank-samples.ts` — распознавание рангов карт и тестовая выборка.
- `telegram.ts` — Telegram-уведомления для проблемных обменов и повторной авторизации.
- `server.ts` — локальная панель управления "Обмены": история, настройки, авторизация Mangabuff и запуск/остановка безопасного цикла.

Подробный маршрут и принятые решения описаны в `docs/browser-workflows.md`.

Новые файлы в `src/` добавляем только когда текущие файлы стали слишком большими или появилась отдельная ответственность: например браузерная сессия, чтение обменов или Telegram.

## `docs/`

Документация проекта для разработчика и ИИ-агентов.

Здесь стоит хранить заметки о структуре проекта, архитектурные решения, исследование Mangabuff и инструкции, которые помогают продолжать разработку без повторного разбора PRD.

## `docs/agents/`

Служебные инструкции для ИИ-агентов.

Эти файлы объясняют, какой issue tracker используется, какие triage-метки применять и где искать доменную документацию. Обычная разработка бота почти никогда не требует менять эту папку.

## `node_modules/`

Установленные зависимости npm.

Эту папку не редактируем руками и не коммитим. Она восстанавливается командой `npm install` по `package.json` и `package-lock.json`.

## Будущие папки

Этих папок может пока не быть, но они ожидаемы:

- `dist/` — скомпилированный JavaScript после `npm run build`; не редактируется руками и не коммитится.
- `data/` — локальная SQLite-база и рабочие данные бота; не коммитится.
- `playwright/.auth/` — сохранённая браузерная сессия Mangabuff; не коммитится, потому что содержит авторизационные данные.
