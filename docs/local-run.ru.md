# Локальный запуск бота и веб-панели

Ниже два разных режима. Для обычной работы используй **режим 1: единый
сервер**. В нём один процесс держит API бота и отдаёт веб-панель, поэтому меньше
шансов случайно выключить нужную часть.

## Что должно быть установлено

- Node.js 20 или новее;
- npm;
- Chromium для Playwright;
- рабочие данные Telegram-бота и аккаунта Mangabuff.

Проверить Node.js и npm:

```sh
node --version
npm --version
```

Все команды ниже выполняются из корня проекта:

```sh
cd /Users/daria/projects/baryga-manga
```

## Первый запуск

### 1. Установить зависимости и Chromium

```sh
npm ci
npx playwright install chromium
```

На Linux для установки системных библиотек Chromium может понадобиться:

```sh
npx playwright install --with-deps chromium
```

### 2. Создать локальный `.env`

```sh
cp .env.example .env
```

Открой `.env` и обязательно замени:

```env
MANGABUFF_LOGIN=your_mangabuff_login
MANGABUFF_PASSWORD=your_mangabuff_password
MANGA_TELEGRAM_BOT_TOKEN=your_telegram_bot_token
TELEGRAM_CHAT_ID=your_telegram_chat_id
```

Не отправляй `.env` в чат и не добавляй его в Git. Файл уже исключён через
`.gitignore`.

Для первого запуска оставь безопасные значения:

```env
AUTO_START_BOT=false
SAFE_MODE=true
AUTO_ACCEPT_ENABLED=false
```

Так сервер запустится без автоматического старта рабочего цикла, а бот после
ручного запуска будет только проверять обмены и записывать, что он бы принял.
Он не нажмёт кнопку принятия.

### 3. Авторизовать Mangabuff

Автоматический вход по данным из `.env`:

```sh
npm run auth:auto
npm run check-auth
```

Успешная проверка заканчивается сообщением:

```text
Сессия Mangabuff активна.
```

Если автоматический вход не проходит, используй ручной:

```sh
npm run auth
```

Откроется Chromium. Войди в Mangabuff, вернись в терминал и нажми Enter. Сессия
сохранится в `playwright/.auth/mangabuff.json`.

## Режим 1 — обычная локальная работа (рекомендуется)

### Первый раз или после изменения исходников

```sh
npm run build
npm run serve
```

Открой:

```text
http://127.0.0.1:3017
```

Порядок работы:

1. Не закрывай терминал с `npm run serve`: в нём живут и API, и бот.
2. В панели проверь статус авторизации.
3. Убедись, что выбран безопасный режим.
4. Нажми **Запустить**.
5. Вкладку панели можно закрыть: бот продолжит работать, пока работает сервер.
6. Для штатной остановки сначала нажми **Остановить**, затем останови сервер
   сочетанием `Ctrl+C`.

При последующих запусках, если код не менялся, достаточно:

```sh
npm run serve
```

Если в браузере появилась страница «Панель ещё не собрана», выполни:

```sh
npm run build:web
```

и обнови страницу.

### Автозапуск бота вместе с сервером

Включай его только после проверки безопасного ручного запуска:

```env
AUTO_START_BOT=true
```

После изменения `.env` перезапусти `npm run serve`. Веб-панель не обязана быть
открыта: бот стартует внутри серверного процесса.

## Режим 2 — разработка веб-интерфейса

Этот режим нужен только при изменении React/Vite-интерфейса. Здесь работают два
процесса, поэтому нужны два терминала.

Терминал 1 — API и бот:

```sh
cd /Users/daria/projects/baryga-manga
npm run dev:server
```

Терминал 2 — Vite:

```sh
cd /Users/daria/projects/baryga-manga
npm run dev:web
```

Открывай именно:

```text
http://127.0.0.1:5173
```

Vite отправляет запросы `/api` на `http://127.0.0.1:3017`. Поэтому:

- терминал 1 должен работать всё время;
- локально не задавай `VITE_API_BASE_URL`: встроенного прокси достаточно;
- если выключить только Vite, бот продолжит работать через сервер;
- если выключить сервер на `3017`, панель откроется, но данные и кнопки работать
  не будут.

Не запускай одновременно `npm run run-bot` и бота из веб-панели. Это создаст два
браузерных процесса для одного аккаунта и одной базы.

## Как не допускать падений

### Держать компьютер и процесс включёнными

Закрытая вкладка браузера не мешает боту. Закрытый терминал, перезагрузка или сон
компьютера останавливают локальный процесс.

На macOS можно защититься от автоматического сна на время работы:

```sh
caffeinate -i npm run serve
```

Закрытие крышки Mac всё равно обычно переводит компьютер в сон. Для
круглосуточной работы нужен постоянно включённый сервер или хостинг, а не
локальный ноутбук.

### Не запускать две копии

Одновременно должна работать только одна команда, владеющая ботом:

- либо бот из `npm run serve` / `npm run dev:server`;
- либо отдельный `npm run run-bot`.

Проверить, занят ли порт:

```sh
lsof -nP -iTCP:3017 -sTCP:LISTEN
```

Если новый сервер пишет `EADDRINUSE`, вернись в терминал уже запущенного сервера
и останови его через `Ctrl+C`, затем запусти одну копию снова.

### Не удалять рабочие данные

Для устойчивой работы должны сохраняться:

- `data/baryga-manga.sqlite` — настройки и история;
- `playwright/.auth/mangabuff.json` — сессия Mangabuff.

Не запускай две копии приложения с одним `DATABASE_PATH`. Не копируй
`mangabuff.json` в публичный репозиторий.

### Оставить защитные лимиты

Не уменьшай паузы и не повышай лимиты навигации без необходимости. Проект уже:

- ждёт случайные 30–60 секунд между проходами по умолчанию (в панели задаётся
  минимум, диапазон настройки — 5–180 секунд); после каждого прохода уходит с
  вкладки «Предложения» на другую страницу и пережидает паузу там;
- ограничивает переходы по Mangabuff: 20 в минуту и 300 в час;
- учитывает `Retry-After` при `429`, `502`, `503` и `504`;
- пересоздаёт упавшую браузерную сессию;
- повторяет временные ошибки;
- при CAPTCHA сохраняет текущее видимое окно Chromium и ждёт, пока проверка
  исчезнет автоматически или после ручного подтверждения;
- останавливается на других защитных страницах или запрете доступа.

Бот проверяет исчезновение CAPTCHA каждые две секунды, но сам её не кликает.
При настроенном Telegram он отправляет уведомление о начале ожидания и ещё одно
после продолжения работы. Кнопка остановки прерывает ожидание и штатно закрывает
браузер.

## Быстрая диагностика

Проверить, что сервер жив:

```sh
curl -fsS http://127.0.0.1:3017/health
```

Ожидаемый ответ:

```json
{"ok":true}
```

Посмотреть конфигурацию без вывода секретов:

```sh
curl -fsS http://127.0.0.1:3017/api/diagnostics
```

Проверить сессию отдельно:

```sh
npm run check-auth
```

Типовые ситуации:

| Симптом | Причина | Что сделать |
| --- | --- | --- |
| Панель не открывается | Сервер не запущен или неверный порт | Запусти `npm run serve`, проверь `/health` |
| Панель на `5173` открылась, но кнопки не работают | Не работает API на `3017` | Запусти `npm run dev:server` |
| «Панель ещё не собрана» на `3017` | Нет `dist/web` | Выполни `npm run build:web` |
| `EADDRINUSE` | Уже работает другая копия сервера | Останови старую копию, оставь одну |
| «Нужна авторизация Mangabuff» | Сессия истекла | Выполни `npm run auth:auto` или `npm run auth` |
| «Telegram не настроен» | Нет токена или chat ID | Заполни `.env` и перезапусти сервер |
| Ожидание CAPTCHA | Mangabuff включил проверку | Оставь видимое окно Chromium открытым; бот продолжит после исчезновения проверки |
| Статус `blocked` или access denied | Mangabuff ограничил доступ | Останови бота, проверь сайт вручную, не обходи защиту |
| Chromium executable doesn't exist | Браузер Playwright не установлен | Выполни `npx playwright install chromium` |
| Процесс исчезает после сна/закрытия терминала | Локальная ОС остановила процесс | Используй `caffeinate` или постоянный хостинг |

Логи выводятся в терминал с сервером. При ошибке сохрани последние строки лога,
текст статуса из панели и ответ `/api/diagnostics` — этого обычно достаточно для
диагностики без передачи паролей и токенов.

## Перед включением реального принятия

Сначала убедись, что безопасный режим корректно распознаёт обмены. Только после
этого можно изменить `.env`:

```env
SAFE_MODE=false
AUTO_ACCEPT_ENABLED=true
```

Перезапусти сервер и ещё раз проверь режим в панели. Эти переменные окружения
имеют приоритет над переключателем панели, поэтому при заданных значениях
переключатель не должен использоваться как единственный источник истины.
